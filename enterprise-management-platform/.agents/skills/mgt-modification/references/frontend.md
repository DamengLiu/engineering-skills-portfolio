# 管理后台 前端修改

页面修改先证明运行页面与目标源码一致，再处理查询、列表、详情和交互。未知信息标记为待确认，不根据菜单文案、目录名或相似功能猜测文件。

## 功能索引

| 需求或现象 | 首要入口 | 继续检查 |
|---|---|---|
| 页面改动未生效 | 运行路由 | 组件映射、构建版本、缓存 |
| 查询条件调整 | 查询配置 | `key`、控件、请求参数 |
| 列表字段调整 | 表格列 | `prop`、formatter、排序、导出 |
| 排序失效或结果错误 | 排序事件 | 请求字段、后端映射、数据库列 |
| 详情或回显调整 | 详情组件 | 字段来源、分组、接口响应 |
| 字典显示异常 | 字典组件 | 编码、名称、`dict`、formatter |
| 按钮显示异常 | 页面权限入口 | 指令、状态、资源编码 |
| 导入导出异常 | 操作入口 | 数据范围、模板、字段和文件响应 |
| 请求异常 | API 调用 | URL、Method、参数和 Network |

## 页面身份证

用户明确指定文件的 L0 文案或样式修改，核对目标内容与差异即可；其他页面任务至少确认浏览器 URL 或路由、目标组件文件和一个可识别的组件/API 特征。出现动态路由、同名页面、列表与详情分离或运行结果不一致时，升级为完整身份证：

```text
菜单名称 / 浏览器完整 URL
route name / route path / route matched
列表组件 / 详情组件
组件 name 或 table local-name
列表 API / 详情 API
```

证据优先级为运行时 `$route` 与 `$route.matched`、动态菜单或路由映射、组件与 API 特征。出现以下情况时，先暂停候选文件写入，继续只读核对路由、组件、API 和环境；证据仍无法消除歧义时再向用户澄清：

- 同名或近似候选超过一个。
- 静态路由与运行时路由不一致。
- 截图字段与候选源码不一致。
- URL、菜单和组件不能形成唯一映射。
- 运行产物与当前源码不一致。

方案必须写出“目标路由 → 列表/详情组件”。运行页面未变化时，先检查请求环境、构建版本和缓存，不修改另一个相似页面补偿。

## 需求规格

页面字段较多时整理查询、列表和详情的显示名称、字段/参数、控件、校验、查询方式、字典和备注。明确区分显示文案、字段名、字典名称、字典编码与标签；文案变化通常不等于字段或接口变化。

## 查询、列表与详情

- 查询条件确认 `key`、控件类型、占位文案、校验和后端参数；长度限制同时考虑输入、粘贴、输入法和重置。
- 联想选择确认接口、参数、返回字段和选中后的真实值；异常时区分 404、网关路由和服务版本。
- 列表改名优先复用原 `prop`；删除字段前检查排序、导出、详情和接口依赖。
- 服务端排序需核对表格产生的字段、请求参数、后端映射和数据库列；展示 `prop` 与排序字段不同时显式转换，并验证升序、降序和翻页。
- 详情保持原有分组与布局；接口未返回的字段不得在前端伪造。
- 金额优先使用现有格式化字段；展示值含千分位等格式时，校验、查询、导出和本地比较统一转换为接口约定的原始值。标签增加单位时复核列宽和表头换行。
- 导入导出先确认勾选、当前查询或全部数据的范围语义，并核对模板、字段、文件名、逐行结果和下载响应。

## 公共组件、字典与权限入口

- 使用表格、表单、字典或双签指令前，检查相邻用例、默认配置、空值处理、值与标签顺序和全局加载时机。
- 字典展示由本文件负责；字典接口语义归后端，字典数据与 SQL 归 `database-design`。
- 前端只控制入口展示和交互，真正的权限、状态和双签约束必须由后端保证。
- 不直接修改压缩依赖包解决业务页面问题，除非用户明确要求且具备源码。

## 前端边界

优先复用同目录或直接相邻页面的既有组件和样式。纯前端展示不得顺带改变接口或数据语义；发现后端缺口时标记影响并按主 Skill 路由到后端。
