# 1 定位与诊断

用于已有单表的运行异常或结果疑问，产出有依据的原因判断或下一步检查。

## 1.1 确认实际执行对象

首轮只查当前表目录、直接调用入口及配置。核对实际环境、参数、报错阶段与日志；本地文件与运行现象不符时，确认部署路径、作业版本和加载配置。没有可靠证据时不猜测字段含义、参数来源或根因。

生成排查 SQL 前，沿作业中的源、目标数据源名查其实际加载的配置文件和各自的数据库类型，再分别采用对应方言；源端可能是 DB2 或 MySQL，不能从数据源名称推断。若配置缺失、无法读取，或无法确认目标环境是否使用这份配置，先向用户确认数据库类型和配置版本，不交付声称可直接执行的特定方言 SQL。本地不尝试连接数据库；目标环境的执行结果由用户提供或在另有明确授权与可用连接条件时取得。

mapping 说明预期规则，代码说明实现，日志或经授权查询说明实际结果。三者冲突时记录差异；未执行的 SQL 不是查询结果。

## 1.2 沿实际链路诊断

入口、导入或配置错误沿调用链定位失败阶段。空结果、数量偏少、重复或字段异常沿数据链路检查：

候选源数据 → 业务筛选 → 关联 → 去重或转换 → 写入尝试 → 目标结果。

只展开实际存在且与问题有关的环节。每段列出脚本或 mapping 依据、只读 SQL 或离线检查、已取得结果和差异解释；未执行时列为待验证。关联可能增加记录，去重可能减少记录，不强求各段数量相等；区分目标既有数据与本次写入。

数据问题需要目标环境排查时，按当前作业生成一组可复制执行的 SQL，只保留实际存在的环节：

1. **源端候选数据**：使用作业中的源表、固定筛选和本次参数，先统计并按需抽样；
2. **关联后数据**：保留作业的关联条件，统计各关联缺失或匹配后的数量；
3. **去重或转换后数据**：复用作业已确认的判重键、转换条件或状态过滤，说明该环节预期增减；
4. **目标实际结果**：按目标业务键和本次范围查询当前记录。作业没有批次标识、写入时间或运行日志关联条件时，明确“不能仅凭目标表区分既有数据与本次写入”。

每条 SQL 前写明执行库、数据库类型、脚本依据和结果解释。已知表名、关联键与参数必须直接代入；只有未知信息可保留为待替换项，并在 SQL 前说明。SQL 必须是只读查询，不含 DDL、DML 或连接测试命令。

## 1.3 只读查询与结论

“临时查一下”“只给 SQL”“不要改文件”时不创建或修改交付物。数据库查询另按项目级授权；输出证据、结论、必要的只读 SQL 与待确认项，不强制非数据问题生成 SQL。

只有读取当前作业的表、参数、筛选和关联，或具有可靠 mapping 依据时，才能提供对应查询；仅依据 mapping 时注明尚未与实现核对。资料缺失时只能提供注明假设的“通用排查 SQL”，不能据此判断源端为空或迁移正常。

需要用户在目标环境执行时，按源端关联和筛选、去重或转换、目标实际结果分别给出完整只读 SQL，写明执行库、已代入的本次参数及如何解释结果；若数据库类型或运行参数未确认，先列出缺口并询问，不猜测语法或数值。

证据足以解释本次范围内的结果才能下结论。需修改时转入 [变更影响与修改](02-change-impact.md)，只要求分析时在此交付。相似信号按需查阅 [错误模式集](../../datax-table-migration/references/failure-patterns.md)，不套用旧表结论。
