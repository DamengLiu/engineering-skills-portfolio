# DataX 批量表迁移

以独立单表 Shell 为执行单元，组织可检查、可追溯的批量迁移。

## 1. 适用范围

用于多张表或同一张表多个日期分片的批量编排、实际耗时统计、结果汇总和批次校验。数据库查询、DataX 执行、清理、恢复及其他外部变更，均须取得对应环境、对象、范围和动作的明确授权。

## 2. 核心边界

- 单表负责字段映射、自身数据前检、DataX 写入和业务校验，且可脱离批量入口独立执行；
- 批量导入负责任务编排、日期传递、执行状态、日志和实际耗时汇总，不修改单表业务映射；批量检查对齐任务与执行结果，并在本次核验范围内检查字段数量、每表源目标记录数及可比较的整批总数；
- 已有单表作业的映射、参数或写入问题交由 [单表修改 Skill](../datax-table-modify/SKILL.md) 处理；批量层记录受影响任务、日期范围与补跑边界，再承接其结果；
- 执行前先识别现有入口的参数、预演、失败处理和批量检查能力；迁移源与影响范围展示属于批量预演，具体内容按现有作业可可靠取得的信息确定，不能把某个模块的调用方式套到其他模块；
- 批次级必需前检失败时整批不启动。默认在单表或日期分片失败后记录 `Failure`，继续其他独立任务；同一目标表的后续分片是否继续，按已确认的依赖和重传策略处理；既有脚本采用遇错停止时如实记录，不为符合 Skill 而改写；
- 批量层不强迫失败单元继续写入，不把失败、结果缺失或已执行但异常的校验判为成功；未执行、跳过和待优化信息写入明细，不设置第三种整体状态；
- 批量脚本遵循项目级语言、命名、修改边界和验证规则。批量检查可读取单表 Python 中可靠可得的源查询、目标表和写入列，但不修改、不格式化单表 Python，也不重复检查未修改的单表 Shell；仅在生成或实际修改批量入口脚本，或用户明确要求时执行对应静态检查；
- 不修改 现有迁移平台/DataX 核心代码，不为具体批次把表名、日期、环境或吞吐量写入 Skill。

分片、并发、性能控制、统一日志、定时运行、耗时预估、异常数据留痕与恢复等新增能力须单独明确需求和设计。它们通常由扩展 Skill 或专项设计承接；本公开副本只列出扩展方向，不绑定特定实现。普通任务清单、执行状态、结果文件和失败范围仍由本 Skill 负责；`tasks.conf` 一类清单定义计划，不充当实际失败记录。

## 3. 稳定流程

```text
任务定义：执行计划
  ↓
批量前检：启动结论
  ↓
单表调用：逐单元结果与日志
  ↓
批量校验：阶段结论与补跑清单
  ↓
批次收尾：交付结论与操作说明
```

每阶段承接上一阶段的产物，只生成自己负责的结果；具体参数、预演、失败策略和校验范围按任务与现有脚本确定。

批量层的稳定单位是任务，而不是字段映射。每个任务至少能定位调用入口、目标表或作业身份、运行范围、执行顺序和结果位置；日期参数、分片和重跑范围以该任务及单表 mapping 的已确认规则为准。批量层不自行决定单表的写入、跳过、覆盖或清理策略，只汇总它们的范围、授权状态和实际结果。

五份参考文件按阶段编号，文件内用对应编号的二级标题分层，例如第 2 份使用 `## 2.1`、`## 2.2`。各自围绕本阶段的问题组织内容，不套用统一小节；执行记录只在调用阶段产生，汇总与判定集中在校验阶段，收尾只呈现结论和交接材料。

## 4. 结果原则

批量层从单表结构化结果、经授权的只读统计或稳定 DataX 指标取得记录数、失败数和实际耗时。既有分隔符结果文件只有在字段、转义和状态值具备明确协议时，才作为结构化接口读取；终端对齐表格只供人阅读，不作为解析接口。

批量检查若需复用单表 Python 的源查询、目标表和写入列，先确认实际参数渲染、过滤范围及可读取方式，不因读取源码就假定可以安全导入或执行作业。字段数按已确认映射与写入列核对，不比较源目标物理列数；记录数沿用实际迁移口径。整批总数只在各执行单元范围可相加、目标覆盖规则明确时核对，不能把总写入次数当成最终目标记录数。现有模块若只核对退出状态，应如实说明数据核验尚未实现或尚未执行。

分别报告结果与日志完整性、DataX 执行结果、数据核验结果。本次未要求或未授权的数据核验标为“暂缓/未执行”，说明原因和待办，不据此把已完成的执行检查报为 `Failure`，也不声称数据核验通过。实际执行失败或已开展的必需检查失败，仍按事实记录。只有执行和必要数据核验均通过，才报告“数据迁移完成”。

## 5. 资料路由与完成

- 确认范围、清单和分片时，阅读 [任务定义](references/01-task-definition.md)；
- 判断整批能否启动时，阅读 [批量前检](references/02-batch-precheck.md)；
- 设计调用、失败处理和结果记录时，阅读 [单表调用](references/03-table-execution.md)；
- 汇总执行结果、核验数据和形成补跑清单时，阅读 [批量校验](references/04-batch-verification.md)；
- 交付批次结论或生成模块 README 时，阅读 [批次收尾](references/05-batch-closeout.md)。

新生成符合标准任务清单的批量交付物后，从项目根目录运行 `py .agents/skills/datax-batch-migration/scripts/check_batch_artifacts.py <批次目录>`；检查既有模块时先核对其真实结构，不能因它采用固定清单或共享入口就套用此检查器。离线检查不代替数据库前检、迁移执行和数据校验。各已执行阶段的整体状态只使用 `Success` 和 `Failure`；暂缓事项单独记录，不改变已完成阶段的状态或退出码。
