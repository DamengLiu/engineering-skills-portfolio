# 2 批量前检

承接任务定义的执行计划，在调用第一张表前确认计划与部署现场相符。产出启动结论；只对本次实际检查过的内容负责。

## 2.1 对照计划检查部署

- 按现有入口检查固定任务列表或配置文件；新生成的清单还要核对字段数、顺序、启用状态和脚本名。
- 确认启用的单表 Shell 能唯一定位，并核对真实使用的导入、检查入口及共享脚本；不假定它们都在批次目录内。
- 检查 DataX、Python 项目、配置文件、解释器和脚本实际使用的共同依赖。
- 对照批次基线检查日期、执行单元数量和单表已确认的写入、重跑及清理范围。复用生成阶段的静态检查结果，不重复检查未修改的单表代码。

## 2.2 确认本次检查范围

先识别脚本参数和预演能力：支持 `--dry-run` 时可用它核对清单，并按现有作业可可靠取得的信息展示来源作业、目标表、日期筛选、清理及迁后更新的影响范围；不支持时只做可执行的静态检查，不假称已预演。预演应标出无法确定的范围，不把源码中的条件直接当成实际渲染结果。数据库查询或运行探测须先取得相应授权。未做数据库检查时，只报告已经完成的静态检查，不称数据库前检通过。

跨表、编码、加密、资源容量等检查按具体批次增加，不替代单表自身的日期、长度、必填和键检查。

## 2.3 作出启动判断

本次列为必需的前检项全部成功时，前检阶段记 `Success`。必需项失败或结果缺失时记 `Failure`，不启动该批次。未列入本次范围的数据检查写“暂缓/未执行”、原因及待办；它不否定已经完成的静态检查。需要运行前耗时预评估时，单独确定依据和口径；依据不足写“暂无法可靠估算”。
