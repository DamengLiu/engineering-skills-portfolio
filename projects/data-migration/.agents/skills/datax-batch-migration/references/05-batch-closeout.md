# 5 批次收尾

承接批量校验形成的阶段结论、批次摘要、补跑清单和日志索引，交付本次结果与操作说明，让下一位操作员知道从哪里继续。这里不重新计算任务统计或数据指标。

## 5.1 交付本次结论

引用已核对的批次号、任务摘要、实际耗时、成功与待补范围，以及结果和日志位置。已执行任务失败、必要结果缺失或本次要求的校验失败，按对应阶段的 `Failure` 如实报告；其他独立表的成功结果同时保留。

全部必要执行单元成功、结果与日志齐全且必要数据核验通过时，才能报告“数据迁移完成”。本次只要求执行、数据核验暂缓时，报告“批次执行完成，数据核验待补”，说明原因和后续动作；既不因暂缓否定执行结果，也不把未核验的数据说成通过。预计耗时或总条数只有可靠取得时才引用。

## 5.2 编写模块操作说明

生成或更新模块 README 前，阅读真实的批量入口、检查脚本、任务清单及代表性单表脚本。按操作员使用顺序写六部分；没有对应能力时写明，不补造命令：

1. **概要介绍**：简短目录树、用途，以及批量调度和单表作业的分工。
2. **部署发布**：发布对象、位置、共享入口、相对路径与配置注意点。
3. **批量迁移**：入口、已有预演、迁移与迁后检查；常用命令在前，指定批次、分组和任务启停在后。
4. **单表迁移**：入口、已有前检、实际支持的区间或全量操作及迁后检查。
5. **运行依赖**：实际使用的解释器、DataX、Python 项目、虚拟环境和配置，附不连接数据库的检查命令。
6. **常见异常、错误**：结果与日志位置、最近或指定批次的查看方式，以及失败和重跑时的排查入口。

命令应可复制，示例日期和批次号应标明替换位置。特别核对首个参数是批次号、任务组还是日期，有无 `--dry-run`，失败后继续还是停止，批量检查是否只汇总退出状态。数据核验暂缓时写明待办；将已成功、失败和未执行范围的定位方式交给后续补传操作员。

## 5.3 交接与收尾边界

收尾不自动删除数据、创建快照、恢复或启动补传；这些动作需要独立的范围和授权。补跑清单只是后续工作的依据，不是自动重传承诺。按实际需要归档结果，不创建无人使用的空模板。
