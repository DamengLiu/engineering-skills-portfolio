# 1 需求与字段映射

本文件负责需求澄清阶段，回答三个问题：迁移依据是否可靠、字段如何对应、是否具备生成脚本的条件。

## 1.1 规则优先级

1. 对应环境中可靠的实际表结构；
2. 当前表已经确认的业务规则；
3. 本文件的通用规则；
4. 字段名称或含义推断。

实际结构与已确认规则冲突时，记录冲突并停止，不自行取舍。字段名称只能作为线索，字段角色以中文含义、字段注释、数据字典和确认结果为准。

## 1.3 字段映射格式

统一使用五列：

| 源字段 | 源字段含义 | 目标字段 | 目标字段含义 | 说明 |
|---|---|---|---|---|
|  |  |  |  |  |

说明列写清直接迁移、日期转换、固定值、置空、长度检查、不迁移或待确认项。源表字段没有目标位置时，不得静默跳过，必须写明“不迁移”及依据并取得确认。

多个来源按来源分别列出五列映射，不把不同来源的转换规则混在同一单元格中。另行确认完整判重键、来源优先级、整条覆盖或字段补齐、来源内部重复规则和执行顺序。业务判重键与目标物理主键分别记录，不默认相同。

每个来源的五列表格一行只写一个目标字段；固定值、置空和转换也各占一行。不迁移的源字段写“无”并说明依据。按已确认的目标结构逐项确认该来源应写字段，再核对 mapping、查询输出与 Writer：目标字段不能只出现在其中一处，也不能因其他来源已映射就省略当前来源。历史文档若使用字段组或通配写法，先展开相关范围，不能把数量相同当作字段闭环。

## 1.4 目标字段加密

可靠目标字段资料中以尾随 `*` 标记的字段为目标加密字段；`*` 是资料标记，不属于物理字段名。需求阶段必须去除标记后得到真实字段名，汇总为“目标加密字段”并记录依据。没有标记字段时，明确记录“无”，不得省略该项。

每个目标加密字段仍按五列映射逐来源记录，在说明列写明“写入前加密”。目标加密清单为全表规则，各来源按其已确认写入字段核对适用清单；差异必须说明依据，不能擅自省略应写字段。某来源该字段置空时，是否跳过或保留空值必须依据现有 `dx_encrypt` 行为或已确认规范，不能自行假定。

新作业将该清单定义为 `ENCRYPT_COLUMNS`，并由 `dx_encrypt` 引用。默认以该字段完成已确认的解码和业务转换后的值作为加密输入；已有 `dx_encrypt` 的参考作业保留其 transformer 位置、参数形式和既有行为。加密输入编码、空值行为、算法、密钥或密文长度未获可靠依据时，列为待确认项，不从字段名推断。

## 1.5 数据完整性

来源值不得截断、舍入、裁剪、静默去重或以其他方式丢失。以下情况必须停止脚本生成或迁移：

- 来源值超过目标长度或精度；
- 来源字段有业务含义但没有目标位置，且尚未确认处理方式；
- 类型转换不能保持原值语义；
- 多个来源值映射后合并为同一目标值，且没有已确认的合并规则；
- 字段过滤、去重或默认值会覆盖有效来源数据，且没有明确的表级处理依据。

超长时调整目标字段长度，或重新确认无损映射。任何明确不迁移的源字段都必须在 mapping 文件中保留记录。

## 1.6 字段处理规则

| 场景 | 处理规则 |
|---|---|
| 源表字段在目标表没有对应字段 | 标记为待确认；确认不迁移后记录依据，不静默丢弃。 |
| 目标非必填字段，原表无对应内容 | 置空。 |
| 目标必填字段 | 必须提供来源字段或已确认的无损生成规则，不可置空。 |
| 创建时间、更新时间等审计时间字段，目标表存在而原表无对应字段或来源值为空 | 填写迁移执行时的当前时间；同一作业使用同一个迁移时间值。 |

新表字段有明确同义来源时优先迁移。生效日、失效日等业务日期按字段映射处理；日期、时间、编码、长度、精度和值域都必须显式处理。找不到 DDL、字典或规则依据时，记录为待确认项。

## 1.7 字段长度与精度

写入前逐项检查字符字段的实际最大长度和数值字段的精度。来源值超过目标定义时，不截取、不舍入、不迁移，立即停止并输出字段、目标定义、来源实际值范围和异常记录数。

是否扩容由用户确认。确认扩容时，建议目标长度取来源实际最大长度的 120% 并向上取整；修改目标结构和执行 DDL 仍须取得对应环境、对象和动作的授权。扩容完成后重新执行全部写入前检查。

## 1.8 日期处理规则

日期转换前，先检查来源值是否为 NULL、空字符串或全空格。

生效日期和失效日期按业务含义识别，不依赖某个固定英文名。优先依据中文名称、字段注释、数据字典和已确认映射判断；`EffDate`、`EffectDate`、`FCTV_DATE` 等英文名只能作为线索。注销日期等含义明确指向有效期结束的字段，按失效日期处理。含义不清时列为待确认项，不自行套用规则。

生效日期和失效日期按以下规则处理：

| 生效日期 | 失效日期 | 处理规则 |
|---|---|---|
| 有值 | 有值 | 分别转换并迁移。 |
| 有值 | 为空 | 失效日期允许为空。 |
| 为空 | 有值 | 将失效日期赋值给生效日期，再转换迁移。 |
| 为空 | 为空 | 视为数据异常，停止并确认；不得填充当前时间。 |

创建时间、更新时间等审计时间字段不属于上述有效期配对规则。其来源值为空时，填充迁移执行时的当前时间。

## 1.9 通用默认值

默认值仅用于源表没有对应字段的目标新增字段。存在有效来源时不得用默认值覆盖。

| 字段 | 默认处理 | 使用条件 |
|---|---|---|
| DATA_FCTV_TP | 固定填写 EF01。 | 目标存在、源表无对应字段且没有当前表覆盖规则。 |
| EXPIRE_DATE | 来源无对应字段时置空。 | 目标允许为空且没有当前表覆盖规则。 |
| REMARK | 固定填写 CBPS迁移。 | 目标表新增、源表无对应字段，且没有表级覆盖规则。 |
| RESERVED | 置空。 | 目标表新增的预留字段，且没有专门的预留值规则；目标字段不可空时先确认。 |
| CRE_DT_TM | 填写迁移执行时的当前时间。 | 目标表新增且源表无对应字段；或来源值为空，且没有表级覆盖规则。 |
| UPDATE_DT_TM | 填写迁移执行时的当前时间。 | 目标表新增且源表无对应字段；或来源值为空，且没有表级覆盖规则。 |

## 1.10 mapping 文件

需求确认完成后，即在目标表目录将本次迁移基线、各来源五列字段映射、明确不迁移字段及其依据写入一份 `<target_table>_mapping.md`。一个目标表只保留一份当前有效 mapping；历史 mapping 保持原名，不额外生成第二份 mapping。文件顶部记录：

- 需求状态：`需求确认完成`；
- 确认人；
- 确认日期；
- 可靠结构依据；
- 尚未执行的数据库检查。

多个来源时，一个来源一个映射分节。每个分节独立列出该来源的五列字段映射、固定值或转换、明确不迁移字段及其依据；不把不同来源的字段名、转换规则或不迁移说明挤在同一单元格中。文件末尾单列合并与校验范围，说明来源执行顺序、覆盖规则、清理位置，以及源端、目标端和迁后需要核验的项目。

单表 mapping 文件随脚本一起交付，不写回 Skill。

mapping 是生成、修改和验收的共同依据。用户的新确认替代旧规则时，更新当前有效内容并简短记录变更原因，不把相互冲突的版本同时作为现行规则。修改字段规则时同步核对查询、Writer、前检和核验 SQL 中直接相关的内容。

mapping 顶部用简短小节记录：模式；实际存在的运行参数和源端筛选；写入与重跑处理；`PRE_SQL` 的注释或启用状态。完整数据留存只在当前表有明确需求时补充，不作为常规 mapping 的必填内容。

mapping 需单列“字段加密”小节，以 `目标加密字段：` 后逐项列出真实字段名（无则写“无”），并记录标记依据和处理顺序；脚本生成前逐项核对该清单与 `ENCRYPT_COLUMNS`。加密后的字段不以密文与源值相等作为默认校验口径；只有具备已确认的加密或解密校验方式时，才开展对应的数据校验。

尚未执行的数据库检查与未确认的业务规则分开记录。需求已确认但本地无法连接数据库时，可保存 mapping 并离线生成脚本，列明测试环境执行前必须完成的检查。不能把用户暂不核实的信息写成已验证；关键字段、键或清理规则仍有冲突时，不生成可直接执行的迁移脚本。

## 1.11 生成门禁

以下条件全部满足后才能生成可运行脚本：

- 迁移基线全部确认；
- 目标字段名来自可靠实际结构；
- 源业务键、目标业务键和目标物理主键均已确认；
- 目标必填字段全部有来源或无损生成规则；
- 模式已确认；实际存在的运行参数与筛选、写入与重跑处理及 `PRE_SQL` 状态已记录；
- 目标加密字段已确认，并已记录为真实字段名；
- 字段映射没有待确认项；
- 不存在截断、舍入或其他数据损失规则。

任一条件未满足时，状态为 `需求确认待定`，只输出需求基线、字段映射和待确认项。
