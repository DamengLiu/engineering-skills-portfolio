# 3 迁移前检

本文件只负责单张表在写入前的表、字段和数据条件检查。

## 3.1 输入

- 已确认的源表、目标表结构；
- 五列字段映射；
- 源键、目标键和目标物理主键；
- 日期、长度、必填、值域等表级规则；
- 本次迁移范围、写入与重跑策略；
- Python 项目目录、DataX 目录、配置文件和作业模块。

数据库查询仍须取得对应环境、对象、范围和动作的授权。没有授权时只生成检查 SQL，不声称检查通过。

## 3.2 风险判断

| 类型 | 处理方式 | 常见情况 |
|---|---|---|
| 普通提醒 | 说明后继续 | 可空字段置空、已确认默认值、审计时间填充。 |
| 危险项 | 说明影响并确认 | 明确不迁移的源字段、目标数据清理、表结构与规则不一致。 |
| 错误项 | 立即停止 | 来源值超长或超精度、截断或舍入、必填字段无来源、日期无法转换、字段不存在或无法对应、目标键冲突。 |

## 3.3 检查内容

- `DATAX_HOME` 已设置并导出，DataX 入口和本表使用的 Reader、Writer 插件存在；
- Python 项目目录、配置文件和当前作业文件存在，Shell 作业模块与部署目录对应；
- 源表、目标表及映射字段真实存在；
- 目标类型、长度、精度、是否必填与映射兼容；
- 源查询与目标字段的数量、顺序和含义一致；
- 必填来源字段空值数为 0；
- 业务日期可转换，并符合生效、失效日期配对规则；
- 每个映射字符字段的实际最大长度不超过目标定义；
- 已确认值域不存在非法值；
- 源业务键和映射后目标键不存在未处理冲突；
- 目标物理主键与已确认定义一致；
- 实际源端筛选、目标写入与重跑策略及目标清理条件已经明确。

字段名称只能作为线索，日期和键的角色以中文含义、字段注释、数据字典和已确认映射为准。

长度、精度、非空和键检查以本次目标环境的有效结构为依据，不沿用未经核实的历史上限。同一源字段写入多个目标字段时，分别核对各目标约束。多来源区分来源内部重复与已确认的跨来源覆盖，不将正常重叠判为未处理冲突。

## 3.4 异常统计口径

每项统计注明来源、迁移范围、原始/过滤后/合并后的数据阶段，以及记录数、重复组数或多余记录数等单位；同时说明所用键、目标约束及结构依据。不同阶段的数量不能直接比较，也不能将汇总异常数全部归因于某个字段。

源值为空而目标必填时，报告字段、异常数量与定位 SQL，不默认补空字符串、0 或过滤记录。未执行、查询失败或无法取得结果时明确记录，不填写为 0。

## 3.5 阻断规则

以下任一情况发生时，前检失败并停止迁移：

- 表或字段不存在；
- 必填字段无来源或存在空值；
- 日期无法转换或生效、失效日期同时为空；
- 来源值超过目标长度；
- 来源数值超过目标精度，或转换包含截断、舍入、裁剪；
- 值域不合法；
- 源键存在未处理重复、映射后目标键存在未处理冲突或目标主键不符合确认结果；
- 迁移范围、写入与重跑策略或目标清理条件不明确。

超长值不得截取。输出字段、目标长度、实际最大长度和超长记录数，等待用户确认是否扩容；扩容建议为实际最大长度的 120%，向上取整。未经授权不执行 DDL，扩容后重新运行全部前检。

重复或冲突不得自行去重或合并。单表前检只报告数量、冲突键和人工核验 SQL；需要完整记录留痕、隔离或恢复时，由扩展 Skill 设计并交回单表实现；批量层仅汇总任务结果。

## 3.6 输出

前检结束只输出一张表，标题为“写入前数据检查结果”，列为：序号、检查项、结果、状态。

```text
写入前数据检查结果

序号 | 检查项                   | 结果          | 状态
-----+--------------------------+---------------+-------
1    | 必填来源字段空值数       | 0             | 通过
2    | NODE_NM 实际最大长度     | 35（目标 70） | 通过
3    | 映射后目标键冲突组数     | 0             | 通过
```

- 标题与表格前后各留一个空行；
- 表头、分隔线和数据列必须对齐，禁止输出挤在一起的 `字段|字段|字段`；
- 每个检查项占一行，失败原因写入结果列，不追加第二张明细表；
- 不能取得结果时填写 `未执行`、`查询失败` 或 `未取得`，不得填写 0 或判定通过；
- 不在本表中输出单表或整批耗时评估。

全部必检项为 `通过` 时，前检状态才是 `迁移前检通过`；否则为 `迁移前检失败`。
