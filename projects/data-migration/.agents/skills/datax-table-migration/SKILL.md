# DataX 单表迁移

一张目标表，一套独立交付物；允许一个或多个来源作业，完成需求确认、脚本生成、迁移和校验。

已有单表脚本的排障、修订和影响检查由 [单表修改 Skill](../datax-table-modify/SKILL.md) 负责；本 Skill 保留新建交付物的规则与检查依据。

- 映射文档回答“依据是什么、字段如何对应”；
- Python 回答“迁什么、怎么写”；
- Shell 回答“按什么顺序执行”；
- 核验 SQL 供人工复核；
- DataX 负责真正搬运和只读统计。

单表不依赖批量 Runner，不修改 现有迁移平台/DataX 核心代码。公共运行层暂不抽取；累计完成并真实验证至少 10 个单表案例后，再依据稳定重复部分评估抽取。

## 1. 任务参数

按当前阶段确认必要信息，不提前追问尚未使用的内容：

- 源表、目标表及可靠表结构；
- 参考作业；
- 源端、目标端数据源名称；
- 测试、生产或三方运行环境；
- 全量、增量或指定业务范围，以及日期参数和实际筛选条件；
- 目标写入与重跑策略，以及目标清理规则（若有）；
- 源业务键、目标业务键和目标物理主键；
- 本次只分析、生成脚本，还是继续执行迁移。

## 2. 授权与风险分级

先按完整请求及已有授权确定阶段和风险；只读分析、方案、脚本生成、数据库前检和实际迁移的权限彼此独立，不因前一阶段完成而自动扩大。

| 等级 | 典型范围 | 默认动作与最低检查 |
|---|---|---|
| L0 低风险 | 新建需求的只读分析、方案或文案说明 | 限定目标资料；不连接数据库、不运行 DataX |
| L1 常规 | 单表映射确认和生成四类迁移交付物 | 定位当前表和参考作业；按完整交付范围检查 |
| L2 高风险 | 迁移前检、键或字段语义冲突、公共迁移脚本或配置影响多个作业 | 明确当前表、影响范围和前检方式；数据库只读检查须获明确授权 |
| L3 执行风险 | 目标清理、DataX 执行、迁后数据库校验 | 取得环境、对象、范围和动作的明确授权后，执行 DataX 和必要校验 |

L0 仅在目标文件唯一、没有字段语义或运行条件变化时成立；不满足即升级。L1 的静态检查不能表述为数据库前检或运行验证通过。L2/L3 的数据库和 DataX 边界仍以项目级权限约定为准。

## 3. 资料路由、搜索与验证预算

执行范围、必要修改、可选建议及停止条件遵循 [项目执行约定](../../../AGENTS.md)；本节只补充迁移阶段的资料和检查要求。

- 按当前阶段读取资料：梳理映射时读 `requirements.md`，生成脚本时读 `execution.md`，前检时读 `precheck.md`，迁后校验时读 `verification.md`；不为早期阶段预读无关规则。
- 遇到与既往失误相似的信号，按需读 [错误模式集](references/failure-patterns.md)，先判断通用失效条件，再回到当前表的证据；不逐项回放所有案例。
- 首轮以源表、目标表、参考作业名、字段名或数据源名检索，并限定目标目录；最多保留 20 条关键命中。仅在零命中或候选不唯一时逐步扩大搜索词或目录。
- 先复用已确认的表结构、映射和参考作业证据；来源、字段或运行环境变化时重新核验。一次性读取不回传完整文件或长日志。
- L0 核对分析依据；L1 按 [迁移执行](references/execution.md) 检查完整交付；L2 输出前检结构化结果；L3 输出 DataX 结果和必要校验摘要。检查频次、时长及 CodeGraph 使用遵循项目约定。

## 4. 分析与协作

只要求分析或提供 SQL 时按请求交付，不自动写入文件；数据库查询另按项目级授权。已有作业的运行异常按 [单表修改 Skill](../datax-table-modify/SKILL.md) 定位。具体字段规则引用需求 reference，当前表的有效 mapping 保存业务确认。

## 5. 工作流程

### 5.1 需求澄清

阅读 [需求与字段映射](references/requirements.md)，按规定表单输出迁移基线、五列字段映射和待确认项。

结构和规则的优先级为：可靠实际结构 ＞ 当前表已确认规则 ＞ 通用规则 ＞ 字段名称推断。来源值不得截断、舍入、静默丢弃或以其他方式损失；存在冲突时停止并调整目标结构或映射。

目标字段名、源业务键、目标业务键、目标物理主键、目标必填字段、运行范围、写入与重跑策略及目标清理方式全部确认，且字段映射没有待确认项后，状态为 `需求确认完成`；否则为 `需求确认待定`，只输出映射，不生成可运行脚本。

目标字段资料中以尾随 `*` 标记的字段需要加密。需求阶段从可靠的目标字段资料提取标记，去除 `*` 后以真实字段名记录到 mapping；具体确认和处理规则见 [需求与字段映射](references/requirements.md)。

需求确认完成后即在目标表目录保存一份 `<target_table>_mapping.md`，不等到脚本生成阶段。多个来源按来源分别列出映射；每个来源独立记录字段映射、固定值或转换、不迁移字段及依据，并确认完整判重键、来源优先级、覆盖范围、来源内部重复规则、执行顺序、运行参数与筛选条件、目标写入和重跑策略，以及清理位置（若有）。生产范围还要记录已存在目标记录的处理方式。该文件保存当前有效基线；尚未执行的数据库检查单独记录，不表述为已通过。

### 5.2 脚本生成

按项目执行约定控制改动范围，字段、写入、清理和执行规则以已确认 mapping 为准。未确认重跑策略时，不预设跳过、覆盖或删除目标记录。

阅读 [迁移执行](references/execution.md)，复用已确认的 mapping，在以目标表命名的目录中交付四类文件：

```text
目标表目录/
├─ <source_table>_to_<target_table>.py  # 每个来源一个作业
├─ <target_table>_mapping.md
├─ <target_table>_check.sql
└─ <target_table>_migrate.sh
```

新增 Python、Shell 脚本遵循项目级语言、命名、修改边界和验证规则。Python 内部标识符以 PEP 8 为准；只在生成新的 Python 作业或用户明确要求时检查 PEP 8，格式差异作为待优化项写入日志，不参与 `Success`、`Failure` 或退出码判定。本 Skill 只补充 DataX 单表迁移的交付物结构、业务文件命名、字段对应和运行约束。迁移 Python 文件名保留来源表与目标表业务标识；mapping、核验 SQL 和新建 Shell 均按目标表聚合命名，Shell 使用 `<target_table>_migrate.sh`。历史脚本保持兼容，除非用户明确要求，不因旧文件名或旧方法名进行批量重命名。

新作业存在目标加密字段时，使用 `ENCRYPT_COLUMNS` 集中声明真实目标字段名，并由 `dx_encrypt` 引用该常量。参考作业已有 `dx_encrypt` 时，保留其 transformer 位置、参数形式和既有行为；没有现成实现时，`dx_encrypt` 在该字段已确认的解码和业务转换后、Writer 前执行。不假定加密算法、密钥、密文长度或空值行为。

不把单表案例写回 Skill。通用规则留在 references，当前表的结构依据、确认记录和字段映射只保存在对应 mapping 文件中。

完整交付运行 `scripts/check_artifacts.py <目标表目录>`，核对各来源 mapping、Writer 和可静态提取的查询列，并离线试渲染 SQL 日期参数。加密检查以 mapping 的真实字段清单和逐来源“写入前加密”说明为依据，兼容单字段尾随 `*`；核对 Writer、`ENCRYPT_COLUMNS` 和静态 transformer 参数，动态实现另行复核。对固定值、码值转换、条件分支、默认值、去重或时间生成，额外执行[语义映射复核](references/semantic-mapping-review.md)。字段数量、字段名和 Writer 顺序闭环只证明结构闭环，不能作为内容映射正确的结论。只有完整交付所需检查均完成且通过，才能报告 `脚本生成完成`。工具不可用或检查未执行时说明剩余检查；静态检查不能替代数据库前检和运行验证。

### 5.3 迁移前检

阅读 [迁移前检](references/precheck.md)，只检查当前表、字段、运行条件和待迁移数据的必要条件。前检结束输出一张“写入前数据检查结果”表。

全部通过后状态为 `迁移前检通过`；否则为 `迁移前检失败`，不得启动 DataX。

### 5.4 迁移执行

只有用户明确授权环境、对象、范围和动作时，才运行对应 DataX 作业。执行正常结束且 DataX 错误记录为 0 时状态为 `迁移执行成功`；否则为 `迁移执行失败`。

### 5.5 迁移校验

阅读 [迁移校验](references/verification.md)，核对记录数、重复键、必填字段、固定值和关键业务字段，并提供人工核验 SQL。

必要校验全部通过后状态为 `迁移校验通过`；否则为 `迁移校验失败`。只有迁移执行和必要校验均通过，最终状态才是 `数据迁移完成`。

## 6. 边界

以下内容不加入单表脚本：

- 默认的单表和整批耗时预评估；有明确需求时单独设计；
- 多表顺序、依赖与失败策略；
- 跨表或相对复杂的前置检查；
- 完整记录重排、复杂终端明细和综合报告；
- 相对完整的批量迁移后校验；
- 除目标字段 `*` 标记要求的 `ENCRYPT_COLUMNS` 与 `dx_encrypt` 配置外的加密、编码和中文样本专项检查；
- 额外的失败诊断框架。

## 7. 迭代

只把经过多个真实案例验证、会稳定改变判断的内容沉淀为通用规则。单表映射、键、结构和确认记录留在该表目录，不进入 Skill。
