# 管理后台 修改验证

验证以证明本次目标达成为准，不追求无关的全仓检查。多个类型并存时采用最高风险等级，并组合覆盖实际影响范围。

## 最低验证等级

| 等级 | 典型修改 | 最低验证 |
|---|---|---|
| L1 | 前端交互、局部接口、业务规则 | 限定差异 + 目标静态检查/编译测试 + 页面或最小接口 |
| L2 | 前后端联动、权限、双签、数据库设计、公共契约 | 各层技术检查 + 端到端业务链路 + 持久化回显 |

用户指定更高强度时按用户要求执行。纯文案不要求无关构建；接口、数据库、权限和公共组件不能只凭截图验收。

## 范围与差异

- 修改文件均在当前授权范围内，用户已有修改得到保留。
- 没有未审核重构、生成文件、调试代码或无关格式化。
- 删除或改名的字段已检查查询、列表、详情、弹窗、导出和调用方。
- 最终 `git diff` 只审查本次文件；发现异常扩散立即停止。

## 前端与 Network

- 运行路由、实际组件、源码和构建版本一致。
- 查询、重置、查看、提交、返回及刷新回显符合目标。
- 字典编码、名称、空值和未知值显示正确。
- Network 的 URL、Method、参数位置、Content-Type、日期格式和响应字段正确。
- 排序验证升序、降序、实际请求字段和翻页结果；格式化输入验证提交值符合接口约定。
- 导入导出验证数据范围、模板或文件名、内容和错误结果。
- 404、500 或旧响应已归属到具体环境、网关或服务版本。

## 后端

- 路由可达，DTO/VO、Service 和持久层参数一致。
- 状态、权限、非法值、缺失记录、重复请求和影响行数处理明确。
- 运行了与目标模块匹配的测试、编译或最小接口请求；不能运行时说明原因。

## 数据库

- 数据库设计按 `database-design` Skill 执行，不在此重复。
- 管理后台 业务验收还需确认数据库结果、接口返回和页面展示一致，并验证刷新或重新进入后的回显。
- 未获授权或尚未执行的 SQL 必须标记为“仅提供 SQL”，不能归类为完成。

## 权限与双签

- 前端入口和后端权限、允许状态一致。
- 登录操作人、双签复核人、资源权限和审计字段归属正确。
- 提交待复核、通过、驳回、取消及最终生效状态可区分。
- 复核完成后持久化结果和再次查询符合预期。

## 验证预算与报告

- 同一修改范围集中完成后再运行一次最低充分检查，失败时只针对失败范围追加检查。
- 输出命令、退出码和关键摘要，不粘贴长日志。
- 最终结果仅使用：已完成且已验证、已实现未运行验证、仅方案或 SQL、阻塞未完成。
