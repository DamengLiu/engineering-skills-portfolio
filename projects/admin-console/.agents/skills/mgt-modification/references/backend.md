# 管理后台 后端修改

后端修改从实际请求入口建立调用链，业务规则放在 Service，接口契约保持兼容。通用分层、组件、日志和异常规则以项目 `AGENTS.md` 为准，本文件只补充定位和业务决策要点。

## 功能索引

| 需求或现象 | 首要入口 | 继续追踪 |
|---|---|---|
| 新增或修改接口 | 实际请求 URL | Controller → DTO/VO → Service |
| 参数未生效 | Controller 入参 | DTO → Service → 持久层 |
| 保存后未回显 | 查询与保存接口 | Service → 持久层 → 数据字段 |
| 导入导出不一致 | 独立接口 | 数据范围、DTO、模板、文件响应 |
| 状态操作异常 | Service 状态判断 | 状态来源、合法转换、持久化 |
| 按钮可见但提交失败 | 后端权限与状态 | 资源配置、校验顺序、异常码 |
| 提交后等待复核 | 双签入口 | 资源配置、待复核、最终生效 |
| 重复写入或通知 | 写接口 | 幂等标识、幂等组件、外部影响 |
| 并发冲突 | 业务资源 | 分布式锁、事务边界 |
| 外部系统调用异常 | SDK 调用 | 请求参数、返回码、结果回写 |

## 接口与调用链

- 从浏览器或调用方的实际 URL、Method 和参数定位 Controller，不根据方法名猜测。
- 沿 Controller → DTO/VO → Service → Repository/Mapper 追踪必要链路，保持字段、类型、校验和返回结构一致。
- 修改既有接口前检查前端和其他调用方；不得为单个功能创建新的统一响应、分页或异常体系。
- 导入导出作为独立接口契约，明确勾选主键或查询条件、模板结构、逐行结果、文件名和下载响应，不默认复用列表语义。
- 接口未返回页面所需字段时明确后端缺口，不要求前端伪造。

## 业务状态

- 状态含义、合法值、转换条件和拒绝结果由 Service 明确；未知状态不得默认解释为正常。
- 保存操作确认业务定位键、允许状态、影响行数、缺失记录和多行命中的处理。
- 不加入未经证据确认的更新条件，不擅自复用字段承载新语义；确需临时兼容时记录风险。
- 状态业务规则归本文件，字段类型、默认值、约束和索引归 `database-design`。

## 权限与双签

- 权限以服务端校验为最终边界，前端入口仅改善交互；两端的资源编码和允许状态必须一致。
- 先搜索项目已有双签指令、资源配置和成功用例，公共机制不能满足时才提出新设计。
- 区分登录操作人、双签复核人和审计字段；登录人不得被 `reviewer_id`（虚构示例字段）替代，复核人只从框架认证后的可信上下文获取。
- 区分“提交成功”“进入待复核”和“复核通过后生效”，明确通过、驳回、撤销及再次查询结果。
- 对未生效、冻结、注销等状态逐项确认入口和后端规则，不以宽泛默认值兜底。

## 持久层边界

数据库设计触发范围以 `AGENTS.md` 为准。普通 SQL、Entity/PO、Mapper/XML 局部调整只检查数据库规范适用章节和受影响映射；结构、字段语义、值域、约束及复杂映射方案变化进入 `database-design`。本文件负责业务语义和调用影响，相关组件统一按 `AGENTS.md` 使用。
