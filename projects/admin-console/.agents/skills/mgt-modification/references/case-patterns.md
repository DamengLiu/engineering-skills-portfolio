## C01 字典编码与名称由公共组件拼接

- **现象**：接口标签只有名称，页面显示“编码 + 空格 + 名称”。
- **根因**：项目表格组件 字典模式可能按 `withValue`、分隔符和先值后标签的默认规则拼接。
- **容易误判**：把编码重复写入数据库标签。
- **决策规则**：先确认列 `type`、`dict`、formatter 和组件默认模式，不直接修改压缩包。
- **验证**：接口 `dictValue`、`dictLabel` 与页面文本对应，标签不重复存编码。

## C02 字典字段含义或长度错误

- **现象**：出现 `Data too long for column 'CATEGORY_CODE'` 或无法按类型加载。
- **根因**：字段语义混淆，或未确认长度和既有数据。
- **容易误判**：只缩短字符串，不核对字段含义。
- **决策规则**：使用 `database-design` 确认表结构、字段语义、数据和回滚方案。
- **验证**：数据库、字典接口键和页面 `dict` 三者一致。

## C03 框架已有双签能力

- **现象**：业务要求双签，初步准备新增审批链路，或双签通过后操作人、复核人记录错误。
- **根因**：项目公共框架 已通过双签指令和资源配置提供通用能力。
- **容易误判**：只看业务 Controller，混用不同双签范式，或用复核人替代登录操作人。
- **决策规则**：先追踪前端触发、请求拦截器、认证上下文、资源配置和成功案例；登录操作人与双签复核人分别取值，框架不能满足时才设计新链路。
- **验证**：检查双签凭据只作用于目标请求，复核人具备资源权限，操作人、复核人、状态和最终数据正确。

## C04 源码更新但浏览器请求旧服务

- **现象**：本地代码有新字段，页面仍返回旧响应或保存失败。
- **根因**：真实 Request URL 指向旧服务，或运行的不是当前构建产物。
- **容易误判**：继续修改前端回填逻辑。
- **决策规则**：先核对 Network 的 URL、端口、响应和服务版本。
- **验证**：请求指向预期环境，新字段返回，保存后重新进入可回显。

## C05 位图或状态码映射错误

- **现象**：数据库位图正确但部分权限不回显，或未知状态显示为正常。
- **根因**：过滤后按位置切分改变索引，或宽泛默认值掩盖未知值。
- **容易误判**：归因于数据库没有更新。
- **决策规则**：固定键顺序，明确索引、默认值、非法值和未知状态策略。
- **验证**：用非连续选中样例完成查询、展示、修改、保存和再次查询。

## C06 单文件修改触发全仓格式化

- **现象**：少量修改产生数百个无关差异。
- **根因**：运行了全仓 lint/format `--fix`。
- **容易误判**：把工具差异当作必要修改。
- **决策规则**：修改前记录状态，只运行限定范围检查；异常时立即停止。
- **验证**：最终差异仅包含审核范围。

## C07 局部正常不等于扩展需求已验收

- **现象**：一个字段已正常，随后增加列表、详情或 SQL，最终状态不清楚。
- **根因**：没有持续维护当前确认版和验收范围。
- **容易误判**：把局部验收当成整个需求包完成。
- **决策规则**：新要求标记为新增、替换或扩大范围，只把明确验证部分标为已验收。
- **验证**：最终逐项区分已验证、未运行验证、仅方案或 SQL、阻塞未完成。

## C08 动态路由下误改同名页面

- **现象**：源码配置看似正确，但运行页面不变化，最终发现修改了同名或近似页面。
- **根因**：根据菜单文案、目录名或功能猜测组件，没有证明运行路由到源码组件的映射。
- **容易误判**：把问题归因于缓存、后端字段或旧构建，继续在错误目录补丁。
- **决策规则**：修改前建立页面身份证，优先检查运行时路由，再核对动态菜单或路由映射；候选不唯一时暂停写入并继续只读定位，仍无法确认时再澄清。
- **验证**：菜单、URL、route、列表/详情组件、组件特征和 API 对应，截图关键字段可在目标组件定位。
